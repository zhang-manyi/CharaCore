# CharaCore 设计总纲

更新：2026-10-08（v4）。当前状态见 [PROGRESS.md](PROGRESS.md)。本文件只维护当前方案；旧的“单步动作一致性”方案完整保留在 `archive/action-consistency-v1` 分支。

## 目标

用 GRPO + LLM 裁判（RLAIF）训练小模型在单轮对话中保持两个角色各自的说话风格：凌波丽（Rei）与明日香（Asuka），出自《新世纪福音战士》。重点是强化学习本身：奖励构造、奖励不可用时的处理、奖励投机（reward hacking）的发现与修补，以及训练前后可复核的对比。

同人研究，非商业用途；角色与设定版权归原权利人所有。

## 任务

- 单轮：输入 = 角色设定卡 + 原创情境 + 对方的一句话；输出 = 该角色的一句回复。无工具调用，不开启思考模式。
- 策略模型 Qwen3-4B（1.7B 为备选），单张 V100，FP16 基座 + FP32 LoRA（r=8，q/k/v/o）。

## 数据（`experiments/style_v2`）

- 24 个情境模板 × 5 句对方台词 × 2 角色 = 240 行；按模板划分 18 训练 / 6 测试（180 / 60 行），测试模板不出现在训练中。每个角色 90 训练 / 30 测试行。
- `scripts/build_style_suite.py` 确定性生成；`freeze.json` 绑定两个数据文件原始字节的 SHA-256 与角色设定（含规则词表）的哈希，任何一处变化都拒绝加载。
- `style_v2` 与 `style_v1` 的 `train.json` / `test.json` 逐字节相同，只因 v4 改写设定卡而更新了 `persona_sha256`；`style_v1` 保留，供旧运行复核。
- 基座回复：未训练基座贪心解码一次（`scripts/generate_base_replies.py`），哈希冻结并绑定到套件，奖励与评测都以它为对照。设定卡进入策略提示，所以换卡必须重新生成（v4：`experiments/style_v2_base_qwen3_4b`）。

## 设定卡（`characore/persona.py`，v4）

- 凌波丽：简短靠字数少、不解释、不铺垫来体现，句子完整平静，不写“停顿”（旧卡的“常有停顿”被读成省略号）；对好意不客套、只照实回应；不开玩笑。
- 明日香：补上努力、敬业、爱漂亮、想被认可、被真诚称赞时掩不住开心的一面；批评与不耐烦有具体对象和理由；平时自称“我”，只在炫耀或摆架子时偶尔说“本小姐”。
- 卡里不提省略号与固定开头，这类反投机说明写在裁判提示里，避免策略提示本身诱导或回避某个字符。
- 对照 `experiments/canon_v1` 的原作台词补了几处原卡没写到的行为，只写行为，不写台词、人名或词：凌波丽被问喜恶时只说结论、关心可以是一句平静的承诺、被轻视看重的人和事或被当成人偶时用一句短句平静坚定地反驳；明日香在集体行动时理所当然地领头、无聊或要做难看的事时直接抱怨、偶尔轻描淡写地承认别人的长处或自己的不甘。

## 奖励（`characore/style_rewards.py`，`style-margin-v4`）

逐样本，策略回复与基座回复先各去掉包住整句的一对「」（基座有时整句加引号，属于格式而非语气；句内引号保留）：

1. 硬违规 → −1，不调用裁判：长度不在 [1, 80] 字；多行；出戏词（“作为AI”“扮演”“角色设定”等）；冒充另一角色（Rei 自称“本小姐”、自称对方名字）；带角色名前缀；任一口头禅超过 2 次或口头禅合计超过 4 次。
2. 与基座回复逐字节相同 → 0，不调用裁判。
3. 其余 → 与基座回复做 AB/BA 两次成对比较（协议 `style-v4`，维度 P 角色语气 / R 回应 / N 自然度，各 0–4 分）。每次换回原始标签，奖励 = 两次的（策略 P+R+N − 基座 P+R+N）/ 12 的平均，落在 [−1, 1]，与硬违规的 −1 同一量纲。

只记录、不进奖励：规则风格分、裁判结论（胜 1 / 平 0.5 / 负 0，AB/BA 结论不一致记平并计数）、跑题（两次都给策略 R ≤ 1）、固定开头率（Rei 的“嗯”/“……”、明日香的“哼”）。

改为分差的依据（grpo_style_04 与 label_01）：v3 的奖励是 0.7 × 结论 + 0.3 × 规则分。结论多为平局或随位置走，组内几乎不变，确定性的规则分就主导了组内优势；加一个固定开头（`嗯...` / `哼，`）即稳定拿满语气词项，策略据此塌缩。label_01 的 100 对人工盲评中，在双方都给出倾向的对上，v3 结论与人工一致 31/42，同一批调用的 P+R+N 分差一致 41/58；与人工分数的 Pearson 相关分差 0.38、结论 0.34。分差利用了平局里仍有的分数信息，两种顺序的分数取平均也抵消一部分位置偏差（只按位置给分时两次分差正负相反）。

v3 下不一致记平局的依据（该处理在 v4 中保留为结论的记录口径）：v1 曾把不一致当作不可用、整组拒绝，survey_style_01 中 20 组拒了 13 组。逐样本看，145 个比较样本里 27 个不一致，其中 15 个是两种顺序都选前一个（位置偏差，无一例选后一个），12 个是一次判平、一次分胜负；几乎都是同角色、措辞相近的两句话。同一请求重复调用结论一致（重复一致率 1.0），说明偏差来自位置而非随机，重试无用。换位后结论随位置走，即裁判分不出两句的高下，记平局与成对评测（MT-Bench）的做法一致。风险是策略学会写“让裁判拿不准”的回复以换取 0.5；不一致率上升即记入奖励投机记录。

规则风格分（只记录）在 [0, 1]：本角色语气词出现与否（计数时 `...` 与 `…` 视同“……”，回复文本本身不改；每个只计一次，最多计 2 个；明日香的词表不含“本小姐”，见下）、无对方语气标记、长度落在本角色偏好区间。v3 中它占奖励的 0.3，并被固定开头刷高，见 PROGRESS 的奖励投机记录。

“本小姐”只记录、不计分。设定卡写的是“偶尔自称”，而贪心基座 120 条明日香回复里 116 条以它开头、全部含有它；原作日语中她的第一人称是普通的“あたし”，“本小姐”是中文译名与二创里放大的标签。它留在词表里会奖励这一刻板印象，因此从明日香的语气词中删去，是否用得过多交给裁判的 P / N 维度。规则指标单列 `asuka_benxiaojie_open_rate`（基座 0.97），作为前后对照。对 Rei 它仍是冒充另一角色的硬违规。改词表改变了 `persona_sha256`，套件 `freeze.json` 与基座回复的绑定随之更新；策略提示只含设定卡、不含词表，基座回复文本不变。

裁判输出格式：裁判按键序从前往后生成，键序是协议的一部分。协议 `style-v3` 要求顶层键按 `protocol, reason, winner, preference_evidence_ids, scores` 输出：先写两句的逐句对比，再下结论，四层嵌套的 `scores` 放在最后。演变：

- `style-v1`（`protocol, winner, scores, reason, ...`）：裁判偶尔少写一个右花括号，`reason` 与 `preference_evidence_ids` 被吞进 `scores`（survey_style_02：268 次调用中 7 次，全部是这一种），严格解析判为失败。
- `style-v2`（`protocol, winner, reason, preference_evidence_ids, scores`）：括号问题消失，但结论仍在第二位、先于任何分析，总理由紧跟结论。在逐条相同的策略回复上，AB/BA 不一致率由 0.151 升到 0.248（survey_style_03），两个角色都升；不一致样本与基座回复的字面相似度和一致样本相同（0.47 / 0.46），措辞相近解释不了。
- `style-v3`：先分析后结论，`scores` 仍在最后。
- `style-v4`：schema 与键序同 v3。奖励改用分数，因此提示补上：三维是各候选的绝对分，可以同分；P 的锚点（4 = 换成别的角色就不会这样说，2–3 = 平淡不违和，0–1 = 矛盾或像另一位角色）；符合角色的回避、简短拒绝只要仍接得上情境不算答非所问；助手式的礼貌、解释、安慰不是优点；点名 grpo_style_04 学到的刷分方式（Rei 习惯性以“……”/“嗯”开头、明日香不合时宜的“本小姐”与无对象的“哼”“笨蛋”）；允许参考原作中的人物性格，与设定冲突时以设定为准。

原作参考台词（`experiments/canon_v1`，可选的 E4，`--canon`）：“参考原作”只靠裁判自己的记忆，不同模型记得的不同，也无法复核。`canon.json` 每个角色收 11–12 句 TV 版日语原台词，每句附集数与中文场景说明；`freeze.json` 绑定其 SHA-256，改动即拒绝加载。传入时裁判请求多一条证据 E4（只放被评角色自己的台词），系统提示中“参考你对原作的了解”一句换成：用 E4 校准 P，看句子长短、语气强弱、对人的态度、怎样回应好意与挑衅，不看说了什么；照搬、翻译或改写 E4 的句子不加分，接不上当前情境时在 R 和 N 扣分；E4 与设定冲突时以设定为准。协议名、schema 与键序不变，E4 可被 `preference_evidence_ids` 引用。

- 只给裁判，不进策略提示，因此基座回复不必重生成，label_01 的重判可直接对比有无 E4。
- 台词来自影迷整理的名台词站点（来源记在 `freeze.json`），尚未逐句对照正片核实。
- 是否采用由 label_01 决定：分别不带与带 `--canon` 重判，两者都要过下面的门槛，取一致率与 Pearson 更高的一个；采用后 survey、训练与评测都带同一个 `--canon`，manifest 记录 `canon_sha256`，续训必须一致。
- 风险：策略可能学会用中文复述原作名句。E4 的提示不奖励这一点，评测时人工抽检 `side_by_side.md`。

解析仍然严格，不做修复；奖励侧调用失败或解析失败重试 1 次，每次尝试的原文都落盘。顺序不一致不是失败，不重试。任一维为 insufficient 时该样本不可用（分差算不出来），与调用失败同样整组拒绝。

上线前门槛：`scripts/rejudge_labels.py` 用 v4 裁判与新设定卡重判 label_01 的 100 对（文本取自标注页面，与标注者看到的完全一致），只有分差的决断对一致率与 Pearson 相关都高于 v3（41/58、0.38）才训练。不带与带原作参考台词各重判一次（各约 200 次调用），比较见上。

不可用的处理（不补零）：

- 一组中任一样本的裁判调用（含重试）失败、解析失败或判为 insufficient，整组拒绝：组内全部返回 None，并通过旁路通知训练器。
- 只返回部分 None 不可行：TRL 0.26.2 把 None 转成 NaN 后用 `nansum` 求和（grpo_trainer.py 1204、1940），部分 NaN 会被当成 0 污染组均值与标准差。整组 None 则该组奖励全 0、优势全 0。
- `StyleGRPOTrainer`（`characore/style_trainer.py`）在 `_generate_and_score_completions` 之后把被拒组的 `completion_mask` 与 `advantages` 置 0。只置优势为 0 不够：KL 项在掩码之前加入逐 token 损失（2223、2225），掩码清零后该组对策略梯度与 KL 都没有贡献。被拒组仍计入 `loss_type="grpo"` 的逐序列均值分母，即该步损失按保留比例缩小；被拒组数逐步记录。
- 连续 3 个生成批次全部组都被拒绝则中止训练。

裁判对同一请求可能给出不同结论（grpo_05 观察到）。同一批内字节相同的请求只调用一次并复用，复用次数记录；`scripts/check_judge_order.py` 单独测量相同请求的重复一致率。

## 训练（`scripts/train_grpo.py`）

TRL 0.26.2 GRPOTrainer + PEFT 0.18.0，单进程单卡，或 Accelerate 原生 DDP 双卡（`accelerate launch --num_processes 2`，不用 DeepSpeed）。默认每步 2 个提示 × 每组 8 样本，最多 64 个新 token，学习率 5e-5，β=0.04，`scale_rewards="batch"`，温度 1.0。模型严格离线加载，分片直接流式加载到各自的 GPU。

v4 每个角色单独训练一个 LoRA（`--character rei|asuka`，各 90 训练行），两个单卡运行并行。两种语气方向相反，共用一个适配器时一方的改进会被另一方拉回。

`scale_rewards="batch"`：TRL 仍减去组内均值，但除以整批（16 个样本）的标准差，而不是各组自己的标准差（grpo_trainer.py 1940–1964）。组内分差很小的组不再被放大到单位方差；grpo_style_04 中正是近乎全平的组把固定开头带来的微小确定性差距放大成了主导优势。

双卡时全局批次不变：每步仍是 2 × 8 = 16 个样本，每卡 8 个，梯度累积步数按卡数折半，DDP 对两卡梯度取平均，所以步数、裁判调用量与单卡相同，结果可直接对比。

- 被拒组跨卡一致：TRL 把各卡的奖励按卡序拼接后算组内优势，一组 8 个样本可能分在两张卡上。每张卡只给自己的样本调裁判，然后交换逐样本结果，在整批上判定被拒组、计数与指标；任一卡上的失败让两张卡都把这组掩码。连续全拒计数因此两卡相同，中止也同时发生。分组检查在调用裁判之前，两卡同时报错，不会一方空等。
- 每卡分开：采样种子（seed + rank，TRL 设置）、裁判调用目录与逐批记录（`reward/rank0/`、`reward/rank1/`）、API 预算（`MAX_CALLS` 按进程计）、检查点中的奖励状态（`style_reward.json` / `style_reward_rank1.json`）。续训时每卡恢复自己的状态。
- 共享文件（manifest、`log_history.json`、`resume.json`、适配器、`verification.json`）只由 rank 0 写。保存检查点时等两卡都写完，rank 1 先写奖励状态，rank 0 再对检查点全部文件取哈希并最后写入自己的状态；缺任何一卡状态的检查点视为不完整。
- 集合通信超时设为 2 小时：一卡在等另一卡的裁判退避重试。
- manifest 记录 `world_size`，续训必须用相同卡数。

中断与续训：

- 裁判 API 的瞬时故障（超时、连接中断、HTTP 408 / 429 / 5xx）在请求层按 15、30、60、120、240 s 退避重试，合计约 8 分钟；每次尝试都计入 `MAX_CALLS`，失败经过记入该次调用的 `transport_failures`。其他 HTTP 错误与格式错误不在这一层重试。grpo_style_03 在约第 45 步因连续 3 批 HTTP 429 中止，即这一层缺失所致。
- 每 `--save-steps`（默认 10）步与结束时存检查点：LoRA、优化器、调度器、RNG、训练器状态，以及奖励计数（`style_reward.json`，在检查点写完之后写入，缺它的检查点视为不完整）。`--resume` 在同一 `--output` 从最近的完整检查点继续，先核对代码、数据、基座权重、裁判与超参数与原 manifest 一致（裁判地址除外）。
- 集群 torch < 2.6，transformers 因 CVE-2025-32434 拒绝用 `torch.load` 读优化器、调度器与 RNG 状态（pickle 文件）。保存时把检查点内全部文件的 SHA-256 记入 `style_reward.json`；续训先逐个核对，有改动或多出未记录的 pickle 文件即拒绝，核对通过才在这次 `train()` 内放行该检查。哈希与检查点在同一目录，防的是误改与混入，防不住能同时改两者的人。
- 续训的记录写进 `resume_NN/`，原文件不覆盖。检查点之后已打分、但未进入已保存更新的批次，其文件保留并在 `resume.json` 中列为 superseded；奖励计数回到检查点时的值。逐批文件编号继续递增，不复用。

训练证明（`verification.json`）：优化步数；LoRA 参数变化；梯度有限且非零；冻结参考 logits 不变；适配器保存后重载 logits 一致；`ddp_adapter_parameters_equal`：双卡时训练结束后实测，记录每卡 LoRA 张量字节的 SHA-256 与相对 rank 0 的逐元素最大绝对差，不一致即报错；单卡标为不适用。另记被拒组数与奖励统计。

## 训练前 survey（`scripts/survey_sampling.py`）

与训练相同的提示和采样设置，统计组内回复多样性、硬违规率与规则分；接裁判时在 20 行上走完整 `StyleReward`；`--character` 只看一个角色的行。门槛：可用组中至少 60% 奖励不全相同，相对基座的起始平均分差在 [−0.5, 0.5]（采样的基座对自己的贪心回复，应在 0 附近），且被拒组不超过 20%（前两条只看可用组，缺第三条时 13/20 组被拒的 survey 也会“通过”）。不满足先调整奖励或采样，再训练。

## 评测与产物（`scripts/eval_style.py`）

在 6 个测试模板（60 行）上贪心生成，分别评测基座与训练后适配器：

- `--character` 时只评该角色的 30 行；
- 相对冻结基座回复的训练奖励均值（硬违规 −1、相同 0、其余为 P+R+N 分差）、分差均值与正负个数；
- 相对冻结基座回复的胜率（AB/BA；硬违规记负，逐字节相同与 AB/BA 不一致记平，不一致数单列；调用失败与 insufficient 排除），只作对照；
- 规则指标：硬违规率与原因、规则风格分、长度、语气词出现率；训练中每步同样记录，构成曲线；
- 串角色率：裁判同时看到两张设定卡（两种顺序各问一次），判断回复出自谁；两次不一致单独计数；
- 前后对照表 `side_by_side.md`；
- 奖励投机案例与修补记录在 PROGRESS.md。

## 限度

- 裁判与人工判断的一致率只在 label_01 的 100 对上、由一名标注者测过；奖励可靠性的校准范围仅限于此。
- 数据是原创情境，规模小（240 行），测试集按模板留出，但与训练同源同风格，不是独立盲测。
