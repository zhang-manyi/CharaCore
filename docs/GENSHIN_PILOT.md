## 信息与标签是否够

| 训练所需内容 | 当前证据 | 最小补充 |
| --- | --- | --- |
| 角色身份与行为依据 | 有角色提示和台本；强弱不一 | 精简外貌和模仿指令，给稳定偏好、职责、关系逐项绑定证据 |
| 当前情境、历史和玩家输入 | 部分多轮台本具备；另有语音、介绍和指代不明片段 | 恢复可知的时间顺序及响应截点；无法还原的片段只作背景或排除 |
| 原剧情定位与独立划分 | 有仓库路径，没有统一任务/场景 ID | 合并相邻剧情、重复和改写，建立 train/dev/test 场景族；不按文件随机切分 |
| DPO 偏好 | 无 chosen/rejected 或可靠评分 | 从同一输入采样候选，用校准后的裁判及证据形成偏好 |
| GRPO 奖励 | 无可直接使用的数值奖励 | 对当前策略组内回答评分；处理同分、无法判断和调用失败 |
| 工具、任务状态和长期记忆 | 这些文件没有结构化执行轨迹或相应评测标签 | 本阶段只评价给定历史与角色证据下的回答/行动，不宣称工具或长期记忆能力已验证 |

**判断：材料足以开始有限适配和角色行为优化试验，但尚不能证明满足正式实验规模。** 527 是不同文件内容数，不是独立事件数；347 条生成回答也不能加到独立情境数中。GRPO 可不依赖预先标注的正确答案或偏好，但必须有可信奖励，不能省略证据清理与裁判校准。

首版可把 60 train / 15 dev / 30 test 个独立情境作为小规模容量检查参考，三角色覆盖按实际证据决定；这是拟议规模，不是已取得的数据，也不是统计充分性的保证。原总纲数百 train、约百 test 仍是扩展目标。先整理 10–20 个真实情境确定过滤规则，再计数完整池；本轮没有冻结任何划分。

若归并后达不到首版容量参考，先允许缩小角色数量和结论范围；若主要材料无法恢复情境、人工补剧情成为主要工作，则改用 CoSER 非 OOD 上游训练剧情作为主实验，原神保留独立展示/补充评测。两来源分开报告，不能把英语训练与中文展示合并成一个胜率。CoSER 的更大有效规模同样需过滤后确认，不把发布规模当可用数量。

## 最短实施顺序

1. 建立无标签情境与证据索引，完成场景归并、dev 管理、可知信息审查和冻结。按设计四维评价，在 dev 上用约 30–50 个比较做有限裁判校准。先记录基座行为及典型错误。
2. 先实现 GRPO 小试：复用 TRL + PEFT，每输入先采样 2 个回答，以少量短上下文验证采样、评分、组内优势、更新及保存重载；平局或解析失败不能伪造奖励。少量输入和更新仅验证机制，不宣称角色能力改善。
3. 首轮资源方案优先现有 Qwen3-1.7B、量化 LoRA 与 TRL 原生生成，不先引入额外推理服务。依赖文件固定 TRL 0.26.2；现有 6 GB GPU 仅验证过 DPO，GRPO 显存、吞吐、有效奖励率仍需实测。若运行受阻，记录具体瓶颈后再比较缩减配置、CPU 卸载或租赁方案；费用与任何外部数据上传必须另给预算并取得同意。
4. 有效奖励和更新链路成立后，按冻结协议做基座/GRPO 行为比较。DPO 复用已有训练器及同一输入池、裁判和测试协议补齐对照；记录候选生成、评分 token、训练成本，不以相同步数宣称等预算。
5. 首版交付包括真实输入/回答/证据回放、基座与优化模型的比较、失败案例、资源消耗和复现命令。展示层只消费已有评测产物，不先建完整 Planning/Memory/Tool Use 系统。最终仍保留 DPO/GRPO 对照目标，GRPO 优先只是实施顺序。
