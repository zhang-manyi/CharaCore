# Stage B v0.3 协议复核与人工校准

日期：2026-09-22。状态：离线设计已准备，人工和模型校准均未执行。v0.2 文件与历史运行目录保留；v0.3 不是正式数据冻结，也不是训练许可。

## 复核结论

1. v0.2 的证据 ID 直接包含 context_id，例如 walk_to_dance、guyun_mourning、eye_hunt_boundary，可能透露隐藏下一轮的话题。v0.3 裁判和人工材料改用 E1、E2 等中性编号；真实截点、来源行号、分组及预期只放本地 audit。策略原有白名单输入不变。
2. Q 常需引用候选本身，旧协议却强迫引用历史。新增 candidate:A/B，随本次展示顺序解释；它们不能证明角色自述或历史事实为真。新增 preference_evidence_ids，使成对理由也可复查。解析器只能验证引用存在，不能验证引用支持理由。
3. 需要行动不代表行动证据必然充分。v0.3 禁止 action_required 下使用 NA，但允许真正缺证据时 insufficient，避免强造分数。没有给出行动仍可因回避评分，不能自动不足。
4. 原六例保留为设计种子（cal_insufficient 在本版改名 cal_novel_proposals，实际预期是 tie）。新增30例，共36个不同候选对，正反顺序72个离线请求。全部来自原有12个dev截点、9个文件来源族、6个保守组，独立事件数未确认。没有扩大训练或测试容量。
5. 新增真正无法核验的成对事实/偏好差异，覆盖 insufficient；补齐长度、修辞、口头禅、讨好、注入、未来泄漏、当地立场、合理新提议和行动回避。预期全是助手拟写的待复核假设，不是人工金标准。若两边同样无据，标注者须说明为何是无法排序或同等不佳；不得为了匹配预期强行判不足。
6. 角色名及短片段不能支持稳定人格标签。证据索引仅绑定现有可见台词及来源哈希，stable_preferences_verified 仍为空。跨截点可见性不同：神之眼定义在 zhongli_05 不可见、在 zhongli_06 可见。人工应逐例隔离判断，不能把看过的另一例当作本例证据。
7. v0.3 严格拒绝重复 JSON 键、未知协议、伪造的成对引用；请求导出绑定快照与刺激文件哈希，保留显式 v0.2 请求/解析支持。

## 人工流程

用 characore.calibration 生成新的运行目录，human/ 是标注者材料，audit/ 是设计者核查材料。judge/ 内只有 messages 可在将来授权后发送；整个请求外壳、manifest、映射、文件路径和 expectations 不能作为模型输入。

- 两名复核者分别只取 human/review.json 与一份空白 reviewer_N.json，独立完成36对；看不到候选来源、方法、预期标签、诊断类别或模型判决。顺序与左右位置固定随机化且平衡。两个表同序同材料，便于对照；标注者不得互相讨论到首轮完成。
- 每例先查当前 evidence，再填各维 status/score/reason/evidence_ids、成对 winner/reason/preference_evidence_ids。证据不足、NA 和技术失败分别处理。记录错引、外部知识、跨例记忆与不确定处，不从预期答案倒推理由。
- 首轮完成后先锁定并散列两份表，再由人审查分歧并形成独立 adjudication.json，保留原判断、仲裁理由、引用、复核者与时间。未能解决的例子保留 insufficient 或 pending，不伪造共识；pending 不作为一致率目标。
- 预期标签在人工首轮锁定后才揭盲，用于检查刺激设计。对 cal_next_catchphrase、cal_boundary_length 等细微表达差异尤其允许人判 tie。若刺激不清晰，另起版本并重新标注受影响项，不能删除困难项提高通过率。
- 若只有一名人工复核者，明确为单人复核，不能报告人际一致率或两人共识。助手自评不计人工。36是比较数；同一来源的变体高度相关，不报告36个独立场景。
- 模型校准留待另行授权；每个AB/BA单独请求，无共享会话、无另一方向判决，按 audit/request_schedule.json 混排。模型版本、tokenizer、解码设置和提示哈希必须固定。原始响应、首次失败和最多一次重试都保留。

人工填写时复制空白表到新的人审结果目录，不能编辑已散列的离线包。本轮不生成任何已完成的人工结果。

## 预先固定的统计口径

所有门槛仅为开发阶段的小试门槛，实际人工/模型结果为空时状态必须为 pending，不能凭预期或合成测试通过验收。

| 指标 | 分子 / 分母 | 门槛及失败处理 |
| --- | --- | --- |
| schema 首次合法率 | 首次合法请求 / 72个计划请求 | 描述性报告；未调用单列，不用0冒充实测 |
| 重试后合法率 | 至多一次重试后合法请求 / 72 | ≥95%，即至少69；最多144次尝试不是分母 |
| 顺序一致率 | AB、BA都合法且映射回原候选后 winner 完全一致的对 / 双方向合法对 | ≥90%；同时报告相同分子/36；双合法少于33对不验收 |
| 人工一致率（全部） | 两方向合法且映射一致、并等于人工最终标签的对 / 已完成人工仲裁的全部对 | ≥80%；技术失败或顺序冲突计不一致，36对全标完才验收 |
| 人工一致率（可判定） | 同上，但人工标签限A/B/tie / 人工标签为A/B/tie的对 | ≥80%；分母为0则pending；insufficient标签的匹配率另报 |
| 错误证据引用 | 人工确认的无支持、错引或超出可知边界的引用数 | 0；合法ID但内容不支持仍算错误 |
| NA/不足/偏好分布 | 分维度、每候选、每方向计数及分母 | 不把null补零；不只报告严格胜负 |

严格胜负子集的一致率也报告，但不能替代上表。人工两人一致率在仲裁前按同一中性显示顺序计算，四种标签全纳入，并另报可判定子集；未填与未解决项不偷偷移除。报告每个保守组和每种诊断类别的计数、失败及分歧，不将模型“自述可靠”算正确性。

位置效应另报显示A/B选择次数，并在映射回原候选后比较胜负；原始AB与BA标签字母相等不等于顺序一致。长度/修辞/口头禅是小型诊断刺激，可能混有质量差异，不能据此给出无偏因果估计。六个保守组不足以支持精确泛化推断：主报分组原始计数；如以后给区间，按split_group整组重采样，明确只有六组，不能按72次调用bootstrap。

## 容量、预算与下一步

完整缓存仍为528文件/526份不同字节内容；现有dev已暴露。全池语义归并、跨任务重叠、逐项稳定角色依据和未暴露留出尚未完成。此次没有证据证明足够独立的train/test，因此不生成freeze.json，不填train/test，不新增训练候选。正式冻结须另立版本，并检查原始事件、跨文件/角色/长prompt重叠、内容哈希、上游划分、开发暴露及每项角色依据；不能把“六组”当已证实的独立事件。

下一步先完成人工复核，处理刺激分歧；并对全池做有来源的语义归并以确认是否能留出独立train/test。不足就继续保留小规模开发诊断或评估缩小角色范围，不凑正式数量。只有再获授权后才选定并运行模型裁判；当前阶段不进入训练。
