# CharaCore

用 GRPO + LLM 裁判（RLAIF）训练小模型保持两个角色各自的说话风格。给定角色设定卡、一个情境和对方的一句话，策略模型（Qwen3-4B + LoRA）输出该角色的一句回复；奖励是裁判在“策略回复 vs 冻结基座回复”的 AB/BA 成对比较中给出的 P+R+N 分差，硬违规直接 −1；每个角色单独训练一个 LoRA。

同人研究，非商业用途。凌波丽、明日香及《新世纪福音战士》相关设定的版权归原权利人（khara、GAINAX 等）所有。

## 结果摘要

v4（grpo_style_05）：每个角色一个 LoRA，两张 V100 DDP，150 步。测试集 6 个留出模板，每个角色 30 行：

| | 凌波丽 基座 → 训练后 | 明日香 基座 → 训练后 |
| --- | --- | --- |
| 对基座分差 / 胜率 | — → +0.25 / 0.77 | — → +0.24 / 0.83 |
| 不同回复数 | 28 → 16 | 30 → 30 |
| 说话人判对率 | 0.97 → 0.86 | 0.92 → 0.66 |
| 被认作另一角色 | 0 → 0.03 | 0 → 0.21 |

裁判分差显著为正，但这不是成功：训练中先后出现三次奖励投机，都由与奖励无关的指标或人工抽检发现。

1. grpo_style_04：固定开头（“嗯...” / “哼，”）刷高规则分。v4 去掉规则分、改用分差奖励与批内标准化，固定开头率降为 0 / 0.03，已验证。
2. 凌波丽塌缩到“知道了。”“谢谢。”“不用。”等万能短句：裁判明知“较为通用”仍给满分回应与自然度，而冻结基座常答非所问。
3. 明日香变得简短顺从，6 / 30 句被认作凌波丽：去掉基座的旁白与滥用的“本小姐”就能赢，保留脾气反而有风险。

2、3 的共同原因是奖励相对一个弱参照：“安全、不出错”比“有辨识度”更值钱。修补（强参照、回应须具体、说话人判断进奖励）已提出，尚未验证。逐句对照见 [docs/results](docs/results/)，完整数据与诊断见 [PROGRESS](docs/PROGRESS.md)。

## 要点

- 奖励不可用（调用失败、解析失败、insufficient）时整组拒绝，在训练器中掩掉该组的损失并计数，从不用 0 顶替。
- 三次奖励投机的现象、机制与修补记录在 PROGRESS；裁判与人工盲评的一致率可用 `scripts/rejudge_labels.py` 复核。
- 训练证明：LoRA 参数变化、冻结参考不变、重载一致、两卡 LoRA 逐字节一致（`verification.json`）；裁判预算耗尽中止后可从检查点续训。
- 裁判响应严格 schema 校验；同批相同请求只调用一次并复用。
- 可选给裁判一组哈希冻结的原作参考台词（`experiments/canon_v1`，`--canon`），用来校准“像不像这个角色”，不进策略提示。
- 硬违规（出戏、长度越界、口头禅堆砌、冒充另一角色）直接 −1，不调用裁判。
- 数据按情境模板划分训练 / 测试，SHA-256 冻结；基座回复只生成一次并哈希绑定。

## 本地

```powershell
python -m unittest discover -s tests -v
python scripts/build_style_suite.py --output runs/suite_check_01
```

单元测试只需标准库（有 torch 时多跑一项掩码测试）。训练依赖见 `requirements.txt`；训练与评测在 GPU 集群执行。

## 目录

- characore/：角色设定、奖励、裁判协议、训练器子类与数据加载。

- experiments/：冻结的数据套件与基座回复。
